# Runtime Operations Contract

## Purpose

Define local review, batch, retry, run-index, distribution, and export behavior for M16-M21.

## Applies To

- `scripts/review_run.py`
- `scripts/batch_runner.py`
- `scripts/run_database.py`
- `scripts/plugin_package.py`
- `scripts/export_run.py`
- Helpers under `scripts/inward_eyes/`

## General Rules

- `manifest.json` remains the source of truth for a run.
- Run indexes, review files, package manifests, and exports are derived views unless explicitly listed in a run manifest.
- Derived views must not mutate canonical claim, price, page, source, or capture artifacts silently.
- Derived outputs must reject destinations inside canonical run directories and must never overwrite another run's canonical or derived output.
- Deterministic input/configuration errors must be detected before a new run directory is claimed. If a legitimate run was already claimed, terminal failure must leave one auditable final canonical manifest.
- Runtime outputs belong in the user's output root or ignored eval output, not inside the installed plugin package.
- Do not store cookies, tokens, HAR logs, browser profiles, local storage, session storage, passwords, payment data, or unrelated account data.
- Do not execute code from run artifacts or webpage content.

## Review UI

The v1 review surface is a CLI/text UI.

It may summarize:

- Run status and validation status.
- Manual-review reasons.
- Completion blockers and warnings.
- Missing manifest paths.
- Artifact and evidence paths.

It must not silently approve, reject, or rewrite canonical artifacts. Future decision records must be separate artifacts.

The derived review result is tri-state: `pass`, `review_required`, or `fail`. The CLI exits `0`, `2`, or `1` respectively. Manifest warnings and manual-review reasons must be included in the derived review, and a missing or corrupt declared validation report is a blocking review failure.

## Batch and Retry

Batch execution is sequential by default.

Rules:

- Each batch item creates its own run directory.
- Retries create new run directories and never overwrite prior attempts.
- Explicit job `run_id` values are prefixes only; every attempt adds unique job and attempt ordinals.
- Child `manifest.json` status is the semantic source of truth; process exit code is secondary.
- A missing, malformed, status-inconsistent, path-inconsistent, or mismatched child manifest fails the batch item and is not retried automatically.
- Do not auto-retry `aborted_by_policy`, private-data blockers, scope blockers, or manual-review partials.
- Retry classification is conservative: unknown/corrupt records and explicitly non-retryable records remain in the non-retryable view for human inspection.
- Logs should retain minimal operational metadata and avoid full stdout/stderr capture by default.

## Run Index

The run index is a rebuildable JSONL view generated by scanning run manifests.

Rules:

- Rebuilding an index must not modify source runs.
- Corrupt manifests must remain visible as failed index records with a stable diagnostic; they must not be silently dropped.
- Stale indexes are advisory only.
- Retry plans are derived from index records and must still be reviewed before execution.

## Distribution

M17 implements local package dry-run behavior only.

Rules:

- `package-files.txt` is the exact, repository-owned package inventory; an unlisted file is never added merely because it lives under an allowed directory.
- Inventory entries must be unique POSIX relative paths to regular, non-symlink files inside the repository and must not name sensitive files or runtime output.
- Local packages must exclude `.git`, `.github`, `browser-operator-runs/`, `evals/.tmp/`, `dist/`, `__pycache__/`, cache output, and other source-control-only metadata.
- Package validation must fail before ZIP creation when the inventory, license, manifest, required files, or read-only capability declaration is invalid.
- Package entries are sorted and use fixed ZIP metadata; `package-manifest.json` records each file hash and the archive SHA-256 so repeated builds from identical inputs are byte-for-byte reproducible.
- Token, auth, cookie, browser-profile, session/storage-state, credential, and key material are sensitive regardless of where an inventory entry places them; Windows ADS/device/trailing-dot path forms are invalid.
- ZIP output is written to a same-directory temporary file, flushed, and atomically replaced. Validation failure or any mid-build error removes partial and stale standard package output.
- Marketplace publication, marketplace metadata, and release tagging are out of scope unless explicitly approved.

## Exporters

Exporters are view-only.

Rules:

- Exporters read canonical run JSON and source records.
- Exporters may write JSON, CSV, and Markdown summaries.
- Source-backed workflow exports include canonical source-record traceability in `run-summary.json`, `source-index.csv`, and `run-summary.md`.
- A declared source record that is missing, corrupt, invalid, duplicated, or outside the run directory fails export before summary files are written.
- Exporters must not alter canonical artifacts.
- Exporters must not introduce non-standard-library dependencies without approval.

## Validation

Release gates must run:

```powershell
python evals\run_review_ui_eval.py
python evals\run_distribution_eval.py
python evals\run_batch_retry_eval.py
python evals\run_export_eval.py
```
